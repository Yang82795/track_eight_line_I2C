双超声波避障：运行流程图与分阶段调试指南

对应 track_eight_line_I2C 工程中改好的避障代码。 循迹逻辑一行未动；避障部分从「舵机扫描 + 固定延时」重写为「双超声波 + 红外闭环回线」。 下面每张图都对应代码里的一个真实函数，可以对照着看。

现状更新（务必先读）：找线逻辑已修好，但整个绕行动作还没调通

我另外搭了一套全闭环仿真：差速电机 → 车辆位姿 → 红外几何 → PID/避障。 基线结论很清楚：无障碍时小车能完美通过两个 90° 急弯，最大偏离只有 14mm， 说明循迹本身应付得了急弯。但凡是加入障碍物，5 个场景全部失败。

所以把"确定的"和"还不确定的"分开说清楚：
· 已确认可用：循迹过急弯、回线闭环的三个分支逻辑、全程不倒转
· 已确认是错的：原参数横向只能偏出 35mm（几何硬上限，见第 07 节）， 而最宽的障碍需要 120~165mm —— 这是算出来的，不是猜的
· 还没解决：固定时序的绕行动作整体调不通，车会"绕过一半又压回线上"， 然后反复触发避障。第 07 节的参数必须上车实测，别直接拿去做比赛

先说最重要的一件事：「两个超声波扫不到障碍物」不是代码逻辑的错

我把你原来的 Avoid_detect() 全开模式判定逻辑单独抽出来跑了一遍仿真： 左侧 25cm 障碍在第 3 个检测周期就返回 OBS_LEFT，右侧障碍第 4 个周期返回 OBS_RIGHT， 判定机本身工作正常。所以故障点不在「判断有没有障碍」这一步。

那两个超声波都不出声，最可能是下面三件事之一：供电被电机拉垮、 安装角度没对准障碍、烧进板子的固件和这份代码不是同一个。 所以这次改代码里最重要的不是"调参数"，而是加了一个能让这件事一眼看出来的自检输出： 小车静止不动时串口就会实时打印左右距离（见第 6 节），10 秒钟就能定位。

02

排查树：两个超声波都不出声，先查这三样

按顺序走，第一个命中的就是原因。这一节建议配合第 6 节的串口自检一起看。

现象：两个超声波距离恒为 999，避障永不触发
小车静止，打开串口，手放在传感器前面看数值
分支 A —— 摸一下：两个模块的 5V 供电是否稳定？
最常见的硬件坑：电机一动，5V 就塌
HC-SR04 内部有 3.3V 稳压 + 发射驱动电流很大。电池内阻一大，电机启动瞬间电压跌落， 超声波直接不工作。这类故障最像代码 bug，因为静止时一切正常。
怎么确认：把 TB6612 的 STBY 拉低让电机停转，再看串口。如果电机不转时距离正常、一转就变 999 —— 就是它。
怎么修：① 每个 HC-SR04 的 Vcc/Gnd 处各焊一个 10µF + 100nF 陶瓷电容就近去耦； ② 电机两端并 0.1µF 抑制刷子火花；③ 条件允许用独立 5V 给超声波供电，并与 UNO 共地。
分支 B —— 读数有值但永远不变？
模块是好的，但探测锥里没东西 → 安装角度问题
HC-SR04 出厂 R3=392 时探测角小于 15°，是一根很窄的笔直射线。 两个传感器放在车头左右角如果向外撇太多，正前方反而成了两个锥形都照不到的盲区。
怎么修：让两个传感器的轴线与车头前进方向夹角 ≤ 20°，并左右各外撇 10–15° 以覆盖赛道宽度。 高度离地 8–15cm（低于 5cm 容易打到地面误报，高于 20cm 障碍物的下沿可能漏检）。 另外障碍物只有 60mm×60mm 的小目标，太靠边也会漏，务必用实物反复试。
分支 C —— A、B 都不是？
烧进板子的固件 ≠ 你手上这份代码
旧代码用了一堆 #if 模式分支，只要 AVOID_SWITCH_MODE 不是 3， 对应引脚就根本不会被 pinMode 初始化，表现为"那个方向的超声波完全是死的"。 你的 avoid_obstacle.hpp 修改时间晚于 .cpp，很可能就是这个问题。
新版已根治：现在只剩一条代码路径，模式只是运行期的一个变量， 不存在"某个分支没编译进去导致引脚没初始化"这类幽灵故障。

06

分阶段调试指南

按顺序做，不要跳级。每一步都通过再进下一步 —— 出问题时能立刻定位到是哪一层。 烧录时把 DEBUG_SERIAL 改成 1，串口 115200。

  1. 阶段 0 · 静态上电，什么都别动
    小车放在悬空支架上（轮子不接触地面），上电，不按按键。 观察串口输出 —— 新代码在这一步就会持续打印 [US] L=… R=…。
    • 电机不动 ✓（WAIT_START 不下发电机指令）
    • 每 200ms 出现一行 [US] ✓
    通过标准：电机静止 + 串口有 [US] 行
  2. 阶段 1 · 超声波自检（对应第 2 节排查树）
    小车仍然悬空。依次把手掌放在左、右传感器前 20–30cm 处。
    • 看到 cm 从 999 变成 15~30 → 该侧模块 OK
    • 一直是 999 但 us 也是 0 → 模块没工作：查 Vcc/GND/接线/供电
    • 绕障物全放上也不变 → 查安装角度（第 2 节分支 B）
    ⚠ 一定要分别测左右两个。只测一个很容易把"另一侧根本没接"漏掉。 通过标准：左右两侧都能分别读到 15~30cm
  3. 阶段 2 · 单模块分模式验证
    在 avoid_obstacle.hpp 改 AVOID_SWITCH_MODE，烧录，看串口 HIT 标记：
    • 1 只左：只有左侧会变 HIT
    • 2 只右：只有右侧会变 HIT
    • 3 全开（比赛用）
    • 0 全关：纯循迹，用来验证避障有没有干扰循迹
    同时把障碍物放到小车正前方 25cm，确认能触发。 通过标准：三种模式行为都符合预期
  4. 阶段 3 · 只测转向方向（悬空，AVOID_MODE_ALL_ON）
    障碍放左前方 → 电机应左轮快、右轮慢（向右偏）。 障碍放右前方 → 右轮快、左轮慢。 看着轮子转的方向判断对错，别只凭小车跑起来的样子。 通过标准：左右各测一次，方向都反得"正确"
  5. 阶段 4 · 落地实测转角（这一步最花时间，也最容易丢分）
    把车放在白纸上，障碍物放黑线左侧，让它跑一次。
    • 撞上 → 偏出不够，加大 AVOID_TURN_OUT_MS（每次 +40ms）
    • 擦过 → 还是不够，继续加，或加大 AVOID_TURN_OUT_OUTER
    • 绕太远、差点压到场地边 → 减小 AVOID_TURN_OUT_MS
    • 绕过去后回不到线上 → 加大 AVOID_PASS_MS，让第 2 阶段多走一点
    四个障碍物宽度分别是 150/60/120/110mm，以最宽的那个 150mm 为准调。 通过标准：四种宽度都能绕开且回到线上
  6. 阶段 5 · 绕行后回线质量
    重点观察避障结束后车身是否与黑线平行。 如果歪着冲出去再大幅甩头，说明第 3 阶段没成功闭环 —— 把 AVOID_LINE_OK_ERR 从 1.5 放宽到 2.0， 或把 AVOID_LINE_HOLD_MS 从 60 减到 30，让它更早判定"回到线上了"。 通过标准：交还 PID 后几乎不甩尾
  7. 阶段 6 · 全赛道连贯跑 + 终点识别
    把 DEBUG_SERIAL 改回 0，全速跑完整条赛道。 重点验证：
    • 起跑后不会把起点横线当成终点（已有 2s 屏蔽）
    • 避障后不会把回线瞬间误判成终点（已有 5s 屏蔽）
    • 终点确实停车并打印 FINISH! Time: xx s
    • 赛段完成标识（120×50×120mm 的 3D 打印块）会不会被超声波当成障碍绕开 —— 这是必须实测的一项
    通过标准：完整跑通，终点时间打印正确

避障转角怎么调（公式 + 速查）

差速小车没有"平移"这个动作，只能靠两段圆弧拼出横向位移。算清楚就不会瞎试。

转向半径 R = ( 轮距W / 2 ) × ( v外 + v内 ) / ( v外 − v内 )
转过角度 θ = ( v外 − v内 ) / W × t // 弧度
一段圆弧横移 d = R × ( 1 − cos θ ) // θ=90° 时最大，正好 = R

按你现在的轮距 110mm 实算

外/内轮 + 时间R转角横向偏移够不够
78 / 18 @ 340ms（旧参数）88mm53°35mm必撞
68 / 32 @ 950ms（现默认）153mm89°150mm达标
62 / 28 @ 1000ms125mm115°177mm偏大易过头

另外：横向/纵向 = tan θ，所以"既往前走很远、又只偏一点"是矛盾的 —— θ 必须小。 这就是固定时序绕行动作调不进去的根源，只能靠实测逼近。

旧参数（35mm）是确定会撞的，这点不用怀疑。 现在默认的 68/32@950ms 能算到 150mm，理论上够绕开最宽的莫高窟 —— 但这只是单车几何账，绕行途中车会不会提前压回线上，仿真还没调通。 上车第一件事就是量这个数：白纸上放障碍，让它绕完，用尺量车中心横向挪了多少毫米。

比赛当天检查清单

规则：3 次机会取最好一次，每轮上限 5 分钟，15 分钟内用完。所以省时间的是调试，不是比赛。

1电池固定牢，魔术贴或电池盒，不会在撞障碍时弹飞
