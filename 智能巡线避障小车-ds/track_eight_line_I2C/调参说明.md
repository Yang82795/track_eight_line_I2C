# 智能巡线避障小车 · 代码结构与调参速查

> 适用工程：`track_eight_line_I2C`（8路I2C红外 + HC-SR04超声波 + 舵机 + 双直流电机）
> 目标：按比赛规则吃满 **赛段分40 / 避障分40 / 时间分40 / 停止分20**
> **现场执行请对照 → 工程根目录 `现场调试步骤与待定夺清单.md`**（分阶段操作步骤、三组终点对照试验、避障摆位矩阵、记录表、待定夺决策）

## 1. 文件结构

| 文件 | 作用 |
|---|---|
| `track_eight_line_I2C.ino` | 主程序：100Hz定周期 + 状态机(CAR_IDLE/RUN/SEARCH/DONE) + 起点按键 + 终点"先刹后判" + 串口调试 |
| `line_pid.cpp/.hpp` | 巡线核心：I2C读8路 → 连续质心偏差(mm) → PD+弯道减速 → 事件上报(丢线/宽黑) + 软里程 |
| `avoid_obstacle.cpp/.hpp` | 避障：`pulseIn`版超声波(不依赖HCSR04库) + 舵机4点扫描 + 偏出/贴边通过/收尾 |
| `motor_car.cpp/.hpp` | 运动层：`Set_speed/Set_speed_ex/Car_drive/Car_stop/Car_brake/Car_pivot` |

## 2. 上车前必须做的 4 项标定（都在文件顶部 `#define`）

| 项目 | 位置 | 怎么标 |
|---|---|---|
| 传感器极性 | `line_pid.cpp` → `BLACK_IS_ZERO` | 串口看 `m=`：压黑线时对应位应为 **0**。若相反，改成 `0` |
| 传感器间距 | `line_pid.cpp` → `SENSOR_PITCH_MM` | 卡尺量相邻两路红外中心距（常见 10~12mm） |
| 里程系数 | `line_pid.cpp` → `MM_PER_PWM_SEC` | 已按 PWM100≈0.32m/s 估。跑完一圈看最后一行 `d=`(cm)，与真实赛道长(约9~10m)比对后按比例改 |
| 舵机左右 | `avoid_obstacle.cpp` → `SERVO_L*/SERVO_R*` | 打到 `SERVO_L1(80)` 看车头是否朝左；反了就两组宏对调 |
| 超声波/舵机高度 | 结构 | 超声波水平、离地 80~100mm（不要俯视地面） |

## 3. 串口调试输出（`DEBUG_SERIAL 1`，每300ms一行）

```
st1 m=F8 n=0 k=3 e=-5 v=6 t=12 d=345 D=850 L=850 R=850 S=-1
 │   │    │   │   │   │  │   │    │     │     │     └ 避障判定侧别(+1障碍在右/-1障碍在左)
 │   │    │   │   │   │  │   │    │     │     └ 右侧扫描mm
 │   │    │   │   │   │  │   │    │     └ 左侧扫描mm
 │   │    │   │   │   │  │   │    └ 前方距离mm(850=量程内无障碍)
 │   │    │   │   │   │  │   └ 里程 cm
 │   │    │   │   │   │  └ 已跑秒数
 │   │    │   │   │   └ 偏差包络mm(大=正在转弯)
 │   │    │   │   └ 偏差mm(正=线在车右侧)
 │   │    │   └ 黑块形态 k: 0正常(1~4路) 1宽黑(5~7路) 2全黑(8路) 3丢线
 │   │    └ 黑点数(正常1~4, ≥5=宽黑/横线候选, 8=全黑)
 │   └ 8路掩码(1=白底 0=压线)
 └ 状态 0待机 1巡线 2原地找线 3结束
```
事件行：`GO` / `CROSS-FALSE`(发夹误报) / `FINISH-STOP`(终点确认) / `LOST-STOP`(丢线超时停车)

## 4. 主要参数与调整方向

| 参数(位置) | 初值 | 现象 → 调整 |
|---|---|---|
| `Speed_Line` (line_pid) | 100 | 发夹/避障都不出岔子后再 +10 提速（时间分靠它） |
| `Speed_Min` (line_pid) | 85 | 弯道还冲出去 → 提到 90~95 |
| `KPx` (line_pid) | 3.0 | 直道摆头 → 降到 2.2；切弯不足 → 加到 3.5 |
| `KDx` (line_pid) | 4.0 | 高频抖动 → 降到 2~3 |
| `SEARCH_TIMEOUT_MS` (.ino) | 1300 | 丢线后原地转太久 → 减小；常找不回 → 加大(最多 2000) |
| `CROSS_ENV_MM` (.ino) | 32 | **检不到终点** → 加大或设 999；**终点前误停** → 减小 |
| `CROSS_WIDE_CNT` (.ino) | 5 | 终点线黑点数上不到5(斜穿很斜) → 降到 4 |
| `CREEP_CLEAR_MS` (.ino) | 250 | 终点线还没停 → 加大到 300~350；发夹误报停 → 减小 |
| `CROSS_MIN_MM` (.ino) | 4500 | 中段发夹触发判定(看串口出现 CROSS-FALSE) → 加大 |
| `SONAR_TRIGGER_MM` (avoid) | 300 | 撞到障碍/来不及绕 → 加大到 350；正常路上的3D标识乱绕 → 加到 250 保持但要减小误触发 |
| `LINE_OFFSET_MM` (avoid) | 22 | 通过时仍碰到障碍 → 加大到 30~35（同时把 `PIVOT_OUT_MS` 加到 300） |
| `PASS_PWM` (avoid) | 80 | 绕行太慢 → 加到 95；绕行不稳 → 减 |

## 5. 故障排查对照表

| 现象 | 原因/处理 |
|---|---|
| 起步就冲出赛道/不认线 | `BLACK_IS_ZERO` 反了；或传感器离地太高/太低（8~12mm，加遮光罩） |
| 直道大摆头 | `KPx` 太大或 `KDx` 太小；也可能是控制周期被串口拖慢 → `DEBUG_SERIAL 0` |
| 发夹弯处原地打转/反复找线 | `SEARCH_LOST_MS` 太小导致频繁进 SEARCH → 提到 80~100ms |
| 发夹弯停下不动 | `CREEP_CLEAR_MS` 太大把发夹判成终点 → 减小；或 `CROSS_ENV_MM` 太小反而在这里触发 |
| 跑完一圈不停车 | 终点线黑点数不够 → 降 `CROSS_WIDE_CNT`；或闸门没过 → 降 `CROSS_MIN_MM`/`CROSS_MIN_MS` |
| 障碍没被识别 | 超声波装太高/被车头挡住；`SONAR_TRIGGER_MM` 太小；电机噪声干扰 → 给超声波供电加 100µF 电容 |
| 绕行使到一半压回线上撞障碍 | 加大 `LINE_OFFSET_MM`、`PIVOT_OUT_MS` |
| 车体后部越过终点线(丢停止分) | 减小 `BRAKE_MS` 前的车速（降 `Speed_Line`）或减小 `CREEP_MS` |

## 6. 比赛当天流程建议（15分钟/3次机会）

1. 先测一次「只巡线、把障碍拿开」，确认能跑完全程并停车（保住 40+20+时间分）；
2. 再放 1 个障碍物，左右各试一次，确认侧别判定正确；
3. 最后 4 个障碍全放，正式跑。**成绩取最好一次，所以第 1 次务必求稳（可临时把 `Speed_Line` 降到 85）。**
